## 1. 这个项目是什么

一位父亲为 10 岁重度 ASD（自闭症）孩子自研的**神经反馈训练原型系统**。开发者只有你一个人，每天 2–3 小时。

最终形态：孩子戴着 EEG 设备做 n-back 任务，系统实时测额中线 theta，theta 够强就给视觉奖励，试图训练他自主上调 theta。

**本期（原型期）被刻意砍到最小**：

1. 不接硬件，用公开数据集 **ds007169**（n-back EEG，250 Hz，19 导）1 倍速回放，模拟实时数据流；
2. 被试是开发者本人，不涉及孩子；
3. 成功标准是"**五次会话能顺顺当当跑完、数据能复算**"，**不是**"theta 变好了"。指标变好要等硬件和真人，本期不问。

一次正式会话设计成六个阶段 S1–S6，一个都不能跳：

| 阶段 | 干什么 | 本期状态 |
|---|---|---|
| S1 | 装配质检（回放期简化为"数据文件可读"，由 preflight 承担） | ✅ 有（preflight） |
| S2 | 参数确认并**冻结** | ✅ 有（IT4 确认页） |
| S3 | 前测 2 min → 算 EOG 回归系数和 theta 阈值 | ✅ 有（IT4 校准） |
| S4 | 训练：6 block × 2 min，block 间休息 30 s | ✅ 有（IT4，但还没有任务刺激） |
| S5 | 后测 2 min，与 S3 完全相同 | ⬜ IT6 |
| S6 | 收尾、保存六件套、出报告 | ⬜ IT6 |

闭环本身就一句话：

```
读一段(200ms) → 质量判定 → 算 theta → 跟冻结阈值比 → 给/不给反馈 → 记录
      ↑                                                              │
      └──────────────────────────────────────────────────────────────┘
```

## 3. 行话和规矩速查（忘了就查这节）

### 3.1 七条硬约束 C1–C7（违反即返工）

| 编号 | 人话 |
|---|---|
| **C1 方向显式** | 训练方向曾搞反两次。反了**不报错、不崩溃、数据看着完全正常**。所以靶点构造必须显式 `direction="up"`，没有默认值，见 [config.py](../src/bci_sys/config.py) 的 `Target`。 |
| **C2 参数冻结** | S3 结束参数拍成快照，S6 之前**没有任何运行期修改入口**。想改参数只能中止重来，本次数据标记中止。 |
| **C3 不许用未来数据** | 实时环路只能向前看。**头号犯法方式：零相位双向滤波（filtfilt）**——等于预知未来，反馈就是假的，而且不报错。所以 `replay/`（实时）和 `offline/`（离线，允许 filtfilt）**物理隔离、互不 import**，由 [tests/test_boundary.py](../tests/test_boundary.py) 做 AST 扫描强制。两边只共享 `config.py` 和 `io_bids.py`。 |
| **C4 环路内拦伪迹** | 最经典翻车：眨眼 → theta 飙高 → 系统奖励 → 被试学会眨眼。练三个月练出个眨眼技能，全程不报错。所以坏段必须在反馈之前拦下（L1/L2/L3，见第 6 节）。 |
| **C5 坏段只标记不删除** | 坏段：反馈**暂停**（不奖也不罚）、不计入达标率，但**必须记录"此段无效"和原因**。中止率、无效率本身就是本期关键结果。 |
| **C6 反馈数和评估数分开** | 给反馈用的是实时 theta；评效果用的是**行为表现**（正确率、反应时，IT5 才有）。同一个数又给反馈又评效，"指标变好"就可能只是被试学会了操纵这个数。 |
| **C7 硬拦，不靠提示** | 开发者/操作者/被试/评估者都是同一个人，提示对自己没有约束力。参数没确认不许开始、到 25 分钟强制结束不给延长、状态没填不许保存。 |

### 3.2 留痕三铁律 D1–D3

- **D1**：原始数据只写一次，永不修改、永不覆盖（`ds007169/` 只读）。
- **D2**：每次会话必须记录代码版本（[gitmeta.py](../src/bci_sys/gitmeta.py)，短 hash + `-dirty` 后缀；拿不到就记 `unknown`）。
- **D3**：无效/中止的会话只标记，**不删除**。

### 3.3 成功判据 A1–A5（本期全满足才算完）

A1 连续 5 次会话无中断跑完｜A2 5 次数据都能被评估模块读取出结果｜A3 同一评估模块能吃公开离线数据｜A4 同一次会话重跑结果完全一致（字节级）｜A5 单会话按时结束无需人为干预。

**说结论时必须带"在回放模式下"六个字**——阻抗质检、蓝牙丢包、干电极漂移这三件事回放永远验不出，要等硬件。

### 3.4 伪反馈 ABABA（IT7 才做，先有个印象）

5 次会话：第 1/3/5 次真反馈，第 2/4 次**伪反馈**（进度条由固定种子的伪随机序列驱动，与 theta 无关，奖励密度与真反馈匹配）。分配必须**盲化**：不进界面、不进日志摘要、不进控制台；真实分配写独立揭盲文件，5 次跑完才准看。种子要固定并写入参数快照。**5 次、单被试，统计上证明不了任何事，本期不得据此下科学结论。**

### 3.5 两个"钟"

- **数据钟**：回放数据自己的时间（段游标 k，每段 0.2 s）。校准 + 六 block = 600 + 3600 段 = **840 s 数据钟**。
- **墙钟**：现实世界流逝的时间。冻结卡 3 s、block 间休息 5 × 30 s = 153 s **只走墙钟、数据钟暂停**，所以一次完整会话墙钟约 **993 s**。墙钟硬上限 **1500 s（25 min）**，超了强制 `wall_cap` 中止。

### 3.6 "冻结"到底冻了什么

S3 校准 120 s 结束的瞬间一次性冻住三样东西，之后到会话结束不再变：

1. **EOG 回归系数** b_FP1、b_FP2（[10s,120s] 滤波后样本、去均值无截距 OLS，剔除前 10 s 滤波器启动瞬态，27500 个拟合样本）；
2. **theta 阈值** θ_thr（校准期有效成熟段平滑功率的 **P20 分位**——即期望约 80% 的段达标）；
3. θ 滤波器在 120 s 处的末端状态 **zf**（运行期从这里续上，保证流式结果与整段一次性滤波逐点相等）。

冻不住（成熟有效段 < 50、阈值非有限、拟合炸了）→ `freeze_failed` 硬停，不进 S4。

## 4. 四个程序怎么跑

环境：Python ≥ 3.11，**uv 管理**（`uv sync` 装依赖；`uv run ...` 跑命令）。数据默认读项目内 `ds007169/`（955 MB，在 .gitignore 里），可用环境变量 `BCI_DATA_ROOT` 覆盖。

### 4.1 `replay-monitor`（IT1）

```bash
uv run replay-monitor --subj 001                    # 全量 1x 回放（约 16 分钟）
uv run replay-monitor --subj 001 --duration-sec 60  # 只放 60 s，开发/截图用
```

- 终端每秒滚 5 行：`段号 │ t=…s │ Fz p2p …µV │ rate 1.00x │ ◆ 1-back / ✗ dropped`。速率比绿(≥0.98)/黄(≥0.95)/红。
- 产物：`outputs/replay/sub-001/<时间戳>/replay.jsonl` + `run.json`。
- 退出码：0 正常 / 2 数据/preflight 错误 / 130 Ctrl+C 中止。

### 4.2 `theta-probe`（IT2，完全独立的离线程序）

```bash
uv run theta-probe --subj 001     # 硬门控：1→4-back 必须严格单调上升，PASS 才许进 IT3
uv run theta-probe --all          # 7 个推荐被试批量跑，纯参考，退出码恒 0
```

- 流程：preflight → 读 Fz 全程 → **全程零相位 1–30Hz FIR**（离线才允许）→ 按非练习试次 onset 切 1.5 s epoch → multitaper（NW=2）算 4–8Hz 功率 → 按 n-back 档位取中位数。
- 产物：`outputs/theta/001/theta_by_load.csv` + `.png`；`--all` 出 `outputs/theta/all/summary.{csv,png}`。
- 退出码：0 = PASS（或 `--all`）/ **1 = 单调性 FAIL** / 2 = preflight 失败。

### 4.3 `qc-monitor`（IT3）

```bash
uv run qc-monitor --subj 001                      # 全量约 16 分钟
uv run qc-monitor --subj 001 --duration-sec 300   # 限时
```

- 前 120 s 终端灰色 `CAL`（不裁决，只攒校准样本）→ t=120s 打印冻结系数 `b_FP1=… b_FP2=… (frozen)` → 之后每段绿 `✓` 或红 `✗ L1` / `✗ L3` / `✗ L1 L3`。
- 产物：`outputs/qc/sub-001/<时间戳>/qc.jsonl` + `run.json` + `valid_rate_timeline.png`（上轨逐段裁决色带，下轨 30 s 分箱有效率；图是事后汇总，不回流实时路径）。
- 退出码同 replay-monitor：0 / 2 / 130。

### 4.4 `feedback-loop`（IT4，目前的主程序）

```bash
uv run feedback-loop --subj 001                    # live；终端只打印 URL，不自动开浏览器
# 然后浏览器打开 http://127.0.0.1:8000，在确认页点按钮才真正开始（C7）

uv run feedback-loop --replay outputs/feedback/sub-001/<run_id>   # 只读回放，不落盘
```

常用参数：`--subj`（默认 001）、`--port`（默认 8000）、`--data-root`、`--out-dir`。只绑 127.0.0.1，前端无构建链、无外部 CDN（断网可用）。

退出码比前三个多：

| 码 | 含义 |
|---|---|
| 0 | 正常跑完（final） |
| 1 | 引擎线程未预期异常（engine_error；traceback 只进终端不进浏览器） |
| 2 | preflight/数据错误（连输出目录都不会建） |
| 3 | 会话条件不满足：`incomplete_data`（整段不足 4200）/ `wall_cap`（超 25 min）/ `freeze_failed` |
| 130 | 用户主动中止（页面按钮或 Ctrl+C） |

## 5. 一次 feedback-loop 会话的完整时间线

页面严格镜像引擎状态机，**前端没有任何"继续/跳过/延长"按钮**（C7）。八个画面：

1. **确认页**：被试、数据文件名、direction=up、全部冻结参数（up / 6×120s / rest 30s / W=5 / P20 / QC 阈值 / 墙钟上限 1500s）回显。不点"确认参数并开始 S3 校准"什么都不会发生——这是唯一启动入口。
2. **校准屏（S3，数据钟 0→120s，600 段）**：600 个灰格逐段点亮 + `mm:ss / 02:00` 倒计时。**这时候 theta 还不存在**，WS 只推不含数值的 `calib_tick`。
3. **冻结卡（墙钟 3 s，不可跳过）**：显示 b_FP1/b_FP2、θ_thr 实测值、参与定阈段数 n、校准达标率（sub-001 实测 80.0%）、direction=up。
4. **block 运行 ×6（每块数据钟 120 s = 600 段）**：六圆点进度（●○）、BLOCK i/6、本块剩余时间、QC 状态灯；主进度条 = 块内命中/有效（带 80% 白色目标刻线，仅装饰，没有"通过线"）；theta 表 = 当前平滑功率位置 + 黄色阈值刻线。
5. **无效段暂停**：进度条变斜纹冻结、红 chip"✕ 无效段·反馈暂停（L3）"+ 红横幅；分子分母定格，不计入达标率。
6. **休息 ×5（墙钟 30 s，数据钟暂停）**：黄字倒计时 + 上一块达标率（**仅记录，阈值不变**）。平滑窗、滤波器状态、QC 状态跨休息全部保持。
7. **结束屏 finished**：数据 840 s / 墙钟 993.0 s、产物目录、六块达标率与无效段表、"不是疗效结论"声明。
8. **中止屏 aborted**：原因（中文映射）、定格在第几块第几段、提示数据按 D3 保留不删。

**关浏览器/关标签页不中止会话**——引擎和落盘继续跑（防误触浪费一次会话）；重新打开页面靠 snapshot 一次追平。只有页面点"中止会话"或终端 Ctrl+C 才中止。

## 6. 每 200 ms 发生什么（实时数据流）

这是系统的心脏。每段 = 50 个采样点（250 Hz × 0.2 s），全程只向前：

```
Fz / FP1 / FP2 原始信号（µV）
  │  各自过因果 1–30Hz 带通（4 阶 Butterworth，高通串低通，单向 lfilter，zi 跨段延续）
  ▼
QcJudge 裁决
  │  L2（每段都做的扣减，不是门）：Fz_clean = Fz_f − b_FP1·FP1_f − b_FP2·FP2_f
  │  L1（门）：Fz_clean 段内峰峰值 > 100 µV        → 残差太大，坏段
  │  L3（门，否决项）：FP1/FP2 任一路峰峰值 > 200 µV → 眼电大到回归不可信，坏段
  │  valid = (not L1) and (not L3)；L1、L3 可同时命中，原因全记
  ▼
clean 50 点 → 因果 4–8Hz（hp4 串 lp8，单向 lfilter，zi 跨段）→ θ功率 = mean(θ²)（µV²）
  ▼
有效段：功率进 W=5"仅有效段"尾窗求平均 → smoothed；hit = (smoothed ≥ θ_thr)，方向 up
无效段（或功率非有限）：smoothed/hit = null，不入窗、不计数，前端保持上一值 + 亮暂停横幅
  ▼
反馈（进度条）+ 计数 + 写 feedback.jsonl + WS 推帧
```

几个容易记错的点：

- **L2 不是一道"门"，是 EOG 回归扣减本身**，每段都做；L1/L3 才是判无效的门。L3 是**否决项**不是参考项。实测 sub-001 绝大多数坏段是 L3 抓的眼动（全量 526 个坏段里 L3 命中 521、L1 仅 41、两门同中 36）。
- **为什么门判在带通后而不是原始信号上**：原始信号有直流偏置/慢漂移，99.9% 的段 p2p 都超 100 µV，直接判会全灭。只有 1–30Hz 带限后绝对阈值才有意义。
- **为什么校准拟合要剔前 10 s**：因果滤波器启动瞬态会把 OLS 系数污染到离谱（实测能到 −4.8/6.7，扣完反而 99% 超阈）。
- **阈值不硬编码**：运行时由 S3 数据现算。16.77 µV² 只是 sub-001 的实测参照值，代码里没有这个数。
- **达标率口径**：块率 = 块内命中段 / **有效段**（坏段分子分母都不进）；总率 = 六块命中之和 / 六块有效之和。分母为 0 时给 0，不除零。
- **非有限值（NaN/Inf）落盘统一写 null**，禁止裸 NaN token。

## 10. Web 层细节

**HTTP**（[webapp.py](../src/bci_sys/replay/webapp.py)）：`GET /`、`GET /app.js` 静态页；`GET /api/run`（当前 run 目录/status/模式，run.json 写半截时降级读内存 outcome）；live 专有 `POST /api/start`（一次性，二次 409）、`POST /api/abort`（202，终态后 409）；replay 专有 `GET /api/replay?file=<白名单内单一文件>`（白名单外 400，写操作一律 403）。

**WebSocket `/ws`**：连上先收一帧 `snapshot`（全部当前状态），之后收事件帧。每帧信封 `{seq, msg}`，帧类型：`calib_tick`（仅 live、不落盘）/ `freeze` / `seg` / `phase` / `seg` / `block_summary` / `final` / `aborted`。除 calib_tick 外，帧字段与 jsonl 同名行**一字不差**——"浏览器看到的"必须能用落盘文件重算。

- **只许一个连接**：第二个标签页连上后立刻用关闭码 **1013** 拒掉（曾误用 HTTP 码 429，真 websockets 栈会 ProtocolError + traceback 洪泛），被拒页显示红横幅 `#ws-dup-banner` 且不再 300 ms 重连风暴。
- **断连不中止引擎**；重连后 snapshot 追平，桥接循环丢弃追平点之前的陈旧帧；前端发现 `seq ≠ 上一帧+1` 就主动重连取 snapshot，不插值不猜。
- **replay 模式**：一次性取全部帧 + 每帧的 offsets_ms + 相位边界，本地 setTimeout 按 1x 播；暂停/继续、拖动 seek（吸附到该时刻前最近的相位边界，从头 reduce 重建 snapshot）；**全程零写入**（已走查：replay 前后 outputs/ 目录无差异）。金色"回放模式（只读，不落盘）"徽标，中止按钮隐藏。

## 11. 红线和经典坑（按错的代价排序）

1. **单位是 µV，mne 读出来直接就是 µV，严禁再乘 1e6。** 错乘后 theta 功率大 10¹² 倍但曲线形状不变、单调性照样 PASS——静默错误，只有 preflight 的 std∈[5,300] 硬门和 IT3 的 L1 会暴露。
2. **实时路径禁用 filtfilt/零相位/任何双向滤波**，只能 `lfilter` 单向 + zi 延续。新增实时文件会被 AST 边界测试自动扫到；也不许 `from bci_sys.offline import ...`。
3. **direction 必须显式 `"up"`**——方向错不报错，是本项目最阴的错（C1）。
4. **无效段只暂停和记录，不许丢、不许"修"**；不要因为有效率不好看就去调 100/200 µV 阈值或分位——§8 明确"数不好看不许动算法"，只有"算不出数"才许换实现（限时 2 天）。
5. **阈值/系数运行期零入口**；想改 = 中止重来。
6. **离线 θ 的处理顺序**：全程滤波 → 再切 epoch。FIR 825 点（3.3 s）比 epoch（375 点）长，先切后滤会大量补零，结果全废且不报错。
7. **multitaper 的 bandwidth 换算**：mne 要全带宽 `2*NW/T`（NW=2、T=1.5s → 2.667 Hz），不是 NW/T；`normalization="full"` 才保证 µV² 量纲。
8. **通道按名查，不按位置假设**（`channel_index`）；名字 FP1/FP2 大写。
9. **lfilter 不能喂空块**（会返回错误 zf 永久污染 IIR 状态），代码里显式拦了，改滤波代码时注意保留。
10. **证据截图不许摆拍**：IT4 的 10 张图都是 playwright 无头 Edge 驱动真生产入口的自动走查产物；走查脚本 `e:/tmp/it4_pw/walk.mjs` 按约定**不进仓库**。
